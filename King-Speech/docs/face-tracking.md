# Face tracking (экран «Роли · съёмка»)

Трекер лица на `app/role-stage.tsx`: белый глиф «Лицо в кадре», жёлтый с одной подсказкой («Подойди ближе», «Отойди чуть дальше», «Встань по центру», «Смотри в камеру»), красный «Лицо потеряно».

**Приватность:** детекция полностью на устройстве (Google ML Kit, модель вшита в приложение). Кадры уходят из камеры прямо в ML Kit и сразу освобождаются; в JS попадают только 6 чисел. Ни кадры, ни данные лица с телефона не уходят. Статистика дубля (`faceStats`) лежит только в памяти и на сервер не отправляется.

## Файлы

- `lib/faceTrackingCore.ts` — чистый алгоритм (пороги `FT`, `FaceTracker`, статистика дубля).
- `lib/faceTracking.ts` — хук `useFaceTracking` + `getVisionFace()` (безопасная загрузка нативных модулей).
- `lib/visionFaceLoader.native.ts` / `lib/visionFaceLoader.ts` — require нативного стека только на iOS/Android; web/Expo Go → `null`.
- `components/roles/VisionFaceCamera.tsx` — камера VisionCamera: запись видео (1080p, без звука — звук пишется отдельно, как и раньше) + frame processor с детекцией.
- `app/role-stage.tsx` — подключение; при отсутствии модулей остаётся старый `expo-camera` с белым глифом.

## Алгоритм

1. Frame processor получает кадры 480×640 YUV и пропускает всё, кроме одного кадра в 200 мс (~5 fps). ML Kit: `fast`, без landmarks / contours / classification / tracking, `minFaceSize 0.1`.
2. Берётся самое крупное лицо. В JS уходит: есть ли лицо, число лиц, `sizeRatio` (высота бокса / высота кадра), центр (0..1), yaw, pitch. В JS-потоке — только несколько умножений; `setState` вызывается лишь когда меняется статус / подсказка / видимость (шаг 5).
3. Оценки (0..1):
   - размер: 1 при 0.30–0.65, линейно до 0 к 0.12 и к 0.90;
   - центр: смещение от центра (0 = центр, 1 = край): 1 при ≤ 0.15, 0 при ≥ 0.60;
   - ракурс: max(|yaw|, |pitch|): 1 при ≤ 20°, 0 при ≥ 35°.
   - quality = 0.35·размер + 0.30·центр + 0.35·ракурс; если любой фактор < 0.35 — quality ≤ 0.5.
4. EMA (α = 0.35 ≈ 0.5 с) по quality и по каждому фактору. Гистерезис: в `ok` при ≥ 0.60, из `ok` при < 0.52, не чаще раза в 600 мс. Подсказка = худший сглаженный фактор; новая подсказка заменяет старую, только продержавшись 1 с.
5. Нет лица > 0.8 с → `lost`. При возврате лица среднее сбрасывается (без «хвоста»).
6. Нет результатов детекции > 2 с (процессор на паузе / детектор падает) → нейтральный белый глиф.
7. Видимость 0–100 = сглаженное quality × 100. Статистика дубля: % времени ok / adjust / lost, средние quality и видимость — пишется в `RolePerformance.faceStats` для экрана результата.

Все пороги — в `FT` в `lib/faceTrackingCore.ts`.

## Сборка

```bash
cd King-Speech
npm install          # обновит package-lock.json — закоммитить его до EAS-сборки
npx expo install --check   # проверить совместимость версий с SDK 58
eas build --profile development --platform ios     # dev client (internal)
npx expo start --dev-client
# релиз:
eas build --profile production --platform ios
```

В Expo Go экран работает как раньше (без трекинга). Симулятор iOS 26 ML Kit не поддерживает (нет arm64-слайса) — тестировать на реальном iPhone.

## Чек-лист на реальном iPhone (перед релизом)

Для каждого пункта: глиф/подсказка ведут себя ожидаемо, нет мерцания, запись и результат работают.

- [ ] Хороший свет, лицо по центру → белый «Лицо в кадре».
- [ ] Слабый свет (вечер, одна лампа) → нет ложного «Лицо потеряно» при видимом лице.
- [ ] Отойти далеко → «Подойди ближе»; поднести телефон вплотную → «Отойди чуть дальше».
- [ ] Лицо наполовину за краем кадра → «Встань по центру», полностью ушло → красный через ~1 с.
- [ ] Повернуть голову в сторону / вниз > ~35° → «Смотри в камеру».
- [ ] Два лица в кадре → оценивается крупное, глиф не скачет.
- [ ] Очки (в т.ч. с бликами), маска / рука у лица, борода, головной убор.
- [ ] Свернуть приложение во время подготовки и вернуться → камера и трекинг продолжают работать; во время записи — приложение не падает.
- [ ] «Заново» (второй дубль) → видео второго дубля сохраняется и проигрывается на экране результата.
- [ ] Отказ в доступе к камере → режим «только голос» с подсказкой, без падения.
- [ ] 60+ с записи → телефон не перегревается заметно, FPS превью без рывков, видео и звук синхронны.
- [ ] Android (если выпускается): те же пункты на устройстве с Android 8+.
